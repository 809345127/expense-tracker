# 记账本（ExpenseTracker）

自用 iOS 记账 app。纯本地存储，无登录、无服务器，中文界面，人民币。

- 技术栈：SwiftUI（界面）+ SwiftData（本地数据库），均为系统自带框架，零第三方依赖
- 系统要求：iOS 17+
- 主题色：系统蓝 `#007AFF`（深色模式自动切 `#0A84FF`）
- 交互原型（当初对齐设计用）：`design/prototype.html`，浏览器直接打开

## 功能

- **明细页**：按月查看，按天分组、每天有小计；点某行修改，左滑删除；顶部渐变卡片显示本月总支出。
  左上角可**按标签筛选**（可多选）。每行底下写着这笔的**记账时间和创建时间**（精确到秒），
  列表按记账时间倒序
- **统计页**：总支出 / 笔数 / 日均 三个数字，分类占比圆环图，分类排行，以及**按标签排行**
- **记一笔**：金额 + 分类（10 个预设）+ **记账时间**（日期 + 时分）+ 备注（可选）+ **标签（可多选、可选）**
- **私密记录**：一笔账可以标成私密。锁着的时候整个 app 当它不存在（列表、合计、统计全排除），
  连点顶部月份三下过 Face ID 才看得到。详见下面「私密记录」一节
- **导出**：CSV（给 AI 分析用，可直接复制成文本）+ 长图（iOS 没有滚动截屏，由 app 自己画）。
  详见下面「导出」一节
- **标签**：自由标注，一笔可以打多个。用来回答分类回答不了的问题
  ——「这次出差一共花了多少」「哪些能报销」。详见下面「标签」一节

## 导出（2026-08-19 加）

明细页右上角的分享图标进去，有两样东西。**两样都先过私密门**
——锁着的时候导出的内容和你屏幕上看到的完全一致，不会出现「界面上藏着、导出来却带出去了」。

### CSV（给 AI 分析）

一行一笔，六列：`记账时间,创建时间,金额,分类,备注,标签`。时间写成 `2026-08-19 12:18:32`，
AI 不用猜格式；一笔多个标签用 `|` 隔开。范围可选「本月 / 全部」。

两个出口：
- **复制成文本** —— 手机上把文本直接粘进 AI 对话框，比先存文件再上传顺手得多
- **导出 CSV 文件** —— 走系统分享面板，存档或者用 Excel 打开

⚠️ **文件开头补了 BOM**（3 个字节）。不补的话 Excel 会拿系统本地编码去解这份 UTF-8，
中文全是乱码。给 AI 吃无所谓，你自己想用 Excel 打开时就有所谓了。

⚠️ **解锁状态下导出的文件名会带「-含私密」**。免得你解锁时导了一份、回头忘了直接发给别人。

#### ⚠️ CSV 转义不能省（省了会静默算错）

备注是自由文本，逗号很常见（`AA,报销用`）。不转义的话那一行会被多切出一列，
**后面每一列全部错位**——金额挪到分类那一列去。最坑的是这种错谁都不会报错，
AI 读进去照样一本正经地分析，只是结论全是错的。

规则是标准 CSV：字段里出现半角逗号、半角引号或换行时，整个字段用双引号包起来、
里面的引号写两遍。全角逗号（`，`）不需要处理。

2026-08-19 用对抗性输入实测过，并用真正的 CSV 解析器读回来逐字对比：

| 原文 | 导出成 | 解析回来 |
|---|---|---|
| `AA,报销用` | `"AA,报销用"` | ✅ 一个字段 |
| `他说"这顿我请"` | `"他说""这顿我请"""` | ✅ 一个字段，引号还原 |
| 含换行的备注 | 用引号整段包住 | ✅ 一个字段 |
| `全角，逗号` | 原样（不加引号） | ✅ 一个字段 |

演示数据里**故意留了一条备注同时带逗号和引号**（`键帽，"矮轴" 一套`），
让这条路径每次截图都被跑到。别把它改回普通文本。

### 长图

**iOS 没有系统级的滚动截屏**（「整页」那个选项只在 Safari 那类地方有），所以由 app 自己画。

#### ⚠️ 它不是「截屏」，是把内容重新画一遍——所以绝对不能用 List / Lazy 容器

`ImageRenderer` 只画渲染那一刻**已经存在**的子视图。而 `List` 和所有 Lazy 容器都是
「滚到哪才建到哪」，屏幕外的行在那一刻根本不存在 —— 出来的图**只有开头一小截，
而且不报错、不崩**，不数一遍根本发现不了。

所以 `ExportImageView` 用的是老老实实的 `VStack`。行样式直接复用明细页的 `ExpenseRow`
（这也是它不能是 `private` 的原因），分组用同一个 `groupedByDay()` —— 图和界面不会分叉。

实测（演示数据锁定态 14 笔）：出图 `390 × 1632` 点、3 倍图 `1170 × 4897` 像素，
**约 1.9 个屏幕高，14 笔一个不少**。截图 `23-导出-长图（完整14笔）`。

#### ⚠️ 尺寸闸门（不加会闪退）

图占的内存 = 宽 × 高 × scale² × 4 字节，高度跟笔数成正比，所以是**平方级**增长。
一笔约 70 点高，按 3 倍图算：100 笔 ≈ 70MB，500 笔 ≈ 350MB，1000 笔直接 GB 级
——渲染当场 OOM 被系统杀掉，用户看到的就是「点一下 app 闪退」。

所以：
- 清晰度按笔数降档：>250 笔用 1 倍，>100 笔用 2 倍，否则 3 倍
- **超过 600 笔直接不给渲**，界面上提示改选「本月」或者用 CSV

「本月」几十笔怎么都碰不到，但「全部」攒上一两年就会撞线。

#### 其它两个决定

- **固定浅色**。导出的图要发给别人、要存档，不该跟着你当时是不是深色模式变。
  `ImageRenderer` 渲的视图是脱离环境的，所以显式写死 `.colorScheme(.light)`。
- **固定 390 点宽**，不取当前屏宽。换手机之后导出来的图还是一样宽，存档才对得齐。

### 怎么在这台机器上验（点不了屏幕）

`-dumpExport` 启动参数会把 CSV 和长图直接渲出来落到 app 的 Documents 里：

```bash
SIM=9AF63CDD-A064-4C4D-9038-AB631455A8B8
B=com.shize.ExpenseTracker
xcrun simctl launch $SIM $B -seedDemo -openSheet export -dumpExport
DOCS="$(xcrun simctl get_app_container $SIM $B data)/Documents"
cat "$DOCS/dump.csv"            # 核对列有没有错位
cat "$DOCS/dump-count.txt"      # 应导出的笔数
# dump.png 就是长图，用 Pillow 量尺寸、数行数
```

加 `-unlockPrivate` 就是解锁态（应该多出私密那几笔）。

## 私密记录（2026-08-19 加）

有些账不想被别人看到。标成私密之后，**锁着的时候整个 app 表现得像它们不存在**。

### ⚠️ 最重要的一条：藏记录必须连合计一起藏

露馅的从来不是被藏的内容，是**对不上的那个数**。

如果只把行藏起来、顶部的「本月支出」仍旧算上私密那几笔，别人把看得见的几行一加，
发现跟总数差了 328，立刻就知道你藏了东西、还知道藏了多少。统计页的三个数字、
圆环、分类排行、按标签排行，每一个都是同样的漏点。

所以口径是：**锁着的时候，所有数字都按「看不见的就不存在」算**。
实测对账（演示数据的 8 月，两笔私密共 328）：

| | 本月支出 | 笔数 | 8月18日小计 | 统计页日均 |
|---|---|---|---|---|
| 锁定 | ¥2,702.80 | 14 | ¥47.80 | ¥142.25 |
| 解锁 | ¥3,030.80 | 16 | ¥175.80 | ¥159.52 |

实现上只在**一个地方**过滤（`Array<Expense>.visible(unlocked:)`），
明细页的 `visible` 和统计页的 `expenses` 都从它派生 —— 所有数字自动一致，
不会出现「改了列表忘了改合计」。加新的统计口径时**务必也从这两个入口取数**。

### 交互

| | 锁定态（别人看到的） | 解锁态 |
|---|---|---|
| 明细页 | 跟没有这个功能时**一模一样**，零痕迹 | 私密记录出现，标题前带把小锁 |
| 顶部卡片 | 「本月支出 · 共 14 笔」 | 「共 16 笔（含私密）」+ 一颗**显眼的**「私密模式 · 点此退出」 |
| 统计页 | 私密的完全不参与 | 全部算回去 |
| 记一笔表单 | **没有「私密」这一行** | 多一行「私密」开关，新建时默认是开的 |

- **进去**：连点顶部「2026年8月」三下 → Face ID（认不出自动退回输设备密码）。
  明细页和统计页都能进。选月份标题是因为它平时就是一行不可点的普通文字，
  别人不会想到去连点它。
- **出来**：再连点三下，或者点卡片上那颗「点此退出」。
- **自动上锁**：app 切到后台就锁。把手机递给别人之前基本都会先按一下 home 或切走，
  这一下就把门关上了 —— 比指望自己记得手动退出可靠得多。

### 三个实现上不能改错的地方

1. **表单里那一行锁着时必须"不存在"，不是禁用、不是灰掉**。别人点一下右上角的 `+`
   就能看到记一笔表单——只要「私密」两个字露出来，「界面上无痕」当场破功，
   而且比在设置里放个开关暴露得更彻底。
2. **自动上锁判的是 `.background`，不能写成 `!= .active`**。拉控制中心、来通知横幅、
   **以及 Face ID 系统弹窗本身**都会让 app 变成 `.inactive`；按 `!= .active` 上锁的话，
   Face ID 一弹就把自己刚开的门关上，永远解不开。
3. **解锁态要盖住多任务快照**。切走那一瞬间 iOS 会给 app 拍张快照放进多任务卡片，
   不盖住就把私密记录原样露出去了——而多任务卡片恰恰是随手翻手机最容易看到的地方。
   见 `ExpenseTrackerApp` 里那个 `Color(.systemBackground)` 覆盖层。

### 用的是 `deviceOwnerAuthentication`，不是 `...WithBiometrics`

后者只认生物识别、没有密码兜底，戴个口罩就彻底进不去了。
另外 `LocalAuthentication` 是系统自带框架，**免费账号就能用**，
跟桌面小组件那个 App Group 的限制不是一回事。

⚠️ 但它需要 `NSFaceIDUsageDescription`，**没有这一项真机上一调 Face ID 直接闪退**（不是报错）。
这个工程没有 Info.plist 文件（`GENERATE_INFOPLIST_FILE = YES`），所以写在 `project.pbxproj`
的 `INFOPLIST_KEY_NSFaceIDUsageDescription`，Debug / Release 两份配置各一处。

### ⚠️ 它挡不住什么

挡的是**别人拿着你已解锁的手机翻这个 app**。

**挡不住**能拿到手机文件或备份的人——私密记录仍然是明文躺在同一张表里，只是多个
`isPrivate` 标记。要挡那种得整库加密，代价是你自己每次开 app 都要解锁，
以「不想让家人朋友随手看到」这个场景不值得做。

另外**没设锁屏密码的设备直接放行**（`canEvaluatePolicy` 返回 false 那条分支）。
没有任何凭据可验时假装有门，只会把这批记录永久锁死、自己也拿不回来。

### 升级不会丢数据（已实测）

这是这个 app **第一次往已有的表加列**（之前加标签是新增一张表）。属于 SwiftData 自动轻量迁移，
前提是**新字段必须有默认值**（`var isPrivate: Bool = false`）。

2026-08-19 实测：把**手机上那份真实数据库**（2 笔 / ¥51）拷进模拟器容器，
用带私密功能的新版本打开 —— 记录一分不差、app 没崩，表里多出 `ZISPRIVATE` 列、
老记录自动填 0。截图 `21-私密-真机库升级后完好`。

## 两个时间（记账时间 / 创建时间，2026-08-19 加）

明细页每一行底下都有一小行灰字，长这样：

```
记账 12:18:32 · 创建 08-19 12:19:19
```

### 这两个时间分别是什么

| | 记账时间（`Expense.date`） | 创建时间（`Expense.createdAt`） |
|---|---|---|
| 含义 | **这笔钱是什么时候花的** | **这条记录是什么时候写进库的** |
| 谁定的 | 你定。表单里可改（日期 + 时分） | 系统自动，编辑记录时也不会变 |
| 精度 | 到秒 | 到秒 |
| 列表里的形式 | `12:18:32`（不带月日） | 同年 `08-19 12:19:19`；**跨年补上年份** `2026-01-01 00:14:03` |

**为什么记账时间不用带月日**：它所在的那个分组标题（`8月19日 周三`）已经写了是哪天。

**为什么创建时间必须带月日**：补记的账，两个时间根本不在同一天。比如昨晚 19:35 看的电影、
今天上午 11:42 才想起来补记 —— 创建时间只写 `11:42:20` 的话，你会以为是同一天记的。
这一眼就能看出「这笔是当场记的还是后来补的」，也是这两个时间放一起才有的价值。

**为什么跨年还要再补上年份**（`ExpenseRow.createdText`）：列表上唯一的年份锚点是顶部那张月份卡片。
12 月 31 日晚上花的钱、元旦凌晨才补记时，只写 `创建 01-01` 会被读成**同一年**的 1 月 1 日
——看着像「钱还没花就先建了记录」，把 createdAt 的意义整个读反。同年的记录仍旧省掉年份，
免得每行都白白变长。（2026-08-19 实跑格式化确认过这个渲染结果，不是推算。）

### 排序口径

列表按**记账时间倒序**（`SortDescriptor(\Expense.date, order: .reverse)`）。
按天分组只是显示上的分节，不改变组内顺序。

⚠️ **别把「同一秒」当成并列**：`Date` 存的是带小数的时间戳，比较精度远不止到秒。
两笔都显示 `12:18:32` 的记录，实际可能差 800 毫秒，排序完全由这 800 毫秒决定
——那是界面上根本看不到的。后面那个按创建时间的 descriptor 只有在两笔记账时间
**连小数部分都完全相同**时才会被用到（基本只有演示数据和批量导入才可能出现）。

### ⚠️ 时间按手机当前时区显示（出国会看着"不对"）

库里存的是绝对时刻，显示、按天分组、按月过滤全都跟着**设备当前时区**走。
所以人在国外把手机时区改掉之后，一笔北京时间早上 6:30 记的账会显示成前一天的 15:30、
分组归到前一天，甚至从「当月」列表里消失（月初那几笔）。

这是「存绝对时刻 + 按本地时区渲染」的固有语义、本身自洽，也**不是这次改动引入的**
（按天分组一直这么算）。只是以前时分秒不显示、看不出来，现在会第一次肉眼撞见。
一直待在国内就碰不到。

### 不用改数据结构（也就不会动老账目）

这两个字段**本来就在** `Expense` 上，只是以前从没显示过 —— `date` 是表单里那个"日期"
（一直带着时分秒，只是选择器只让选到天），`createdAt` 以前只在后台给同一天内的记录排序用。
所以这次是纯显示改动：**没有新增/删除字段，不触发 SwiftData 迁移，手机上已有的账目一分不差**。

### ⚠️ 秒是自动带的，选择器改不了

iOS 的时间选择器**最细只到分钟**，秒选不了。新建一笔时，秒来自你点开表单那一刻。

所以**当场记的账，两个时间会差几秒**——那就是你从点开表单到点保存花的时间。
实测手机上现有那 2 笔：差 7.4 秒和 8.0 秒。这不是错，但别把这几秒当成"记账精度"。
真正有信息量的是**差了一天以上**的那种：那才是补记。
（手动拨动时间选择器之后，原来的秒是保留还是清零，**还没实测** —— 这台机器点不了屏幕，
见下面「Xcode 27 里没有 Simulator.app」那一节。两种结果都不影响正确性。）

### ⚠️ 时间那一行必须 `lineLimit(1)`，不能只靠「单独占一行」

时间最早是塞在标题那一列里的，会跟标题、金额抢宽度，备注长一点的行就被挤到折行
（断在 `创建 08-19` 和 `12:19:19` 之间）。把它拎出来单独占一整行解决了**默认字号**。

**但只解决默认字号**。2026-08-19 实测：把系统「设置 → 显示与亮度 → 文字大小」滑块
拉到最大档（`xxxLarge`，普通设置、不是辅助功能档），折行原样复现、断点一模一样。
所以还加了 `.lineLimit(1)` + `.minimumScaleFactor(0.75)` 把它定死成一行——
时间是要被读的信息，宁可缩小也不要断成两截。表单里那行「创建时间」同理。

复现方式：`xcrun simctl ui <sim> content_size extra-extra-extra-large` 之后重启 app 截图。

### 颜色用 `.secondary` 不用 `.tertiary`（实测对比度）

第一版这行用的是 `.tertiary`，从截图逐像素量出来对白底只有 **1.84:1**
——同一行的分类名是 4.00:1，标题是 21:1。小字的可读下限是 4.5:1，连大字的 3:1 都够不上，
屏幕调暗或户外就读不出秒数了。改成 `.secondary` 之后是 **4.00:1**，和分类名齐平；
层级靠字号拉开（`caption2` 比分类名的 `caption` 小），不靠把它涂淡。

### 格式化为什么锁 `en_US_POSIX` 而不是 `zh_CN`

`Models.swift` 里这三个格式化属性（`timeTitle` / `stampTitle` / `fullStampTitle`）走的是
写死的纯数字格式串。`DateFormatter` 在普通 locale 下会被系统「12/24 小时制」那个开关影响，
`en_US_POSIX` 是 Apple 明确推荐的「固定格式」locale，输出永远和格式串一字不差。
旁边的 `monthTitle` / `dayTitle` 仍用 `zh_CN`，因为它们要的就是中文月日和「周三」。

## 标签（数据结构与统计口径，2026-08-17 加）

### 分类和标签的分工

- **分类**：这笔钱花在**什么品类**上（餐饮/交通…）。单选、必填、10 个固定值。
- **标签**：**自由标注**，多选、可选。回答分类答不了的问题。

两个维度独立，交叉起来才有价值（比如「出差」标签里餐饮占几成）。

### 为什么单独一张 Tag 表，而不是在记录上存字符串数组

| | 独立 Tag 表（现在的做法） | 在 Expense 上存 `["出差","可报销"]` |
|---|---|---|
| 改名 | 改一处，所有历史记录跟着变 | 得遍历所有记录批量改，漏一条就裂成两个标签 |
| 防重复 | 同一个标签只有一个实体 | `"出差"` 和 `"出差 "` 会变成两个，统计直接分家 |
| 配色/排序/停用 | 有地方放 | 没地方放 |

代价：多对多关系在 SwiftData 的 `#Predicate` 里不好写查询条件，所以**按标签筛选和汇总一律在内存里算**
（见 `Models.swift` 的 `matchingAny`）。一年几千笔的量级，跟统计页原有做法一致，无所谓。

### ⚠️ 两个不同的统计口径，别搞混

| 场景 | 口径 | 为什么 |
|---|---|---|
| 明细页**按标签筛选**（可多选） | **同一笔只算一次钱** | 一笔被选中的多个标签同时命中，只计入一次。实现上是「按记录过滤」而不是「按标签累加」，所以去重是免费的 |
| 统计页**按标签排行**（每标签一行） | **各行之间会重叠** | 「每个标签各自花了多少」的正确答案就是重叠的；所以卡片底部**必须**写清这一点，且不能给一个「合计」数字去骗人 |

实测对账（演示数据的 8 月）：`出差` = 19，`可报销` = 163，同时选这两个标签 → **163**（不去重会算成 182）。

### 名字的清理与查重

存之前统一清理（去首尾空白、中间连续空白压成一个），查重时忽略大小写与全角半角差异
（`Tag.cleanedName` / `Tag.comparisonKey`）。这个 app 在金额上被中文输入法坑过一次（全角句号），
标签同理——肉眼看不出的差异会让同一个标签裂成两个。

**故意没用 SwiftData 的 `@Attribute(.unique)`**：① 它冲突时是静默覆盖而不是报错；
② 以后要开 iCloud 同步的话，唯一约束根本不被支持，到时候还得拆掉。查重放在代码里做。

同理，Tag 的所有属性都给了默认值、关系可空——这是 iCloud 同步的硬要求，现在遵守是零成本。

### 升级不会丢数据（已实测，不是"应该没事"）

加标签这件事对 SwiftData 是纯新增（多一张表 + 一个默认空数组的关系），属于自动轻量迁移。
2026-08-17 实测过：用**改动前的旧版本**在模拟器里写出一个真实数据库（3 笔 / ¥1229.50），
再用新版本打开它 —— 库里多出 `ZTAG` 和多对多中间表 `Z_1TAGS`，原来那 3 笔一分不差，app 没崩。

## ⚠️ 这台 Mac 上 Xcode 的版本坑（2026-08-13 记）

这台机器跑的是 **macOS 27.0 beta**，而 App Store 提供的 **Xcode 26.6 是给 macOS 26 用的**，
点「打开」会弹「此版本 macOS 不支持此 Xcode 版本」。原因不是普通的兼容性提示，而是系统自带一份
不兼容应用名单（`/System/Library/CoreServices/CoreTypes.bundle/.../Exceptions.plist`），
Xcode 在里面被标成 `HardDisabled`，命令行 `open` 也会被拒（错误码 -10664）。这个名单受系统完整性
保护，改不了，也不该改。

**要点：只有图形界面被挡住了，命令行工具链完全正常**——`xcodebuild` 编译、模拟器、`devicectl`
都能用，这个项目就是这么构建和验证的。所以只有"在 Xcode 里登 Apple ID 做签名"这类事才需要 GUI。

解法是装 **Xcode 27 beta**（要求 macOS 26.4 以上、仅 Apple 芯片）：

```bash
brew install xcodes aria2          # aria2 会让下载走 16 线程，快 3-5 倍
xcodes list | grep '^27'           # 看有哪些版本，不需要登录
xcodes install "27.0 Beta 5"       # 要输 Apple ID + 密码 + 两步验证码；免费账号即可
```

装好后它是 `/Applications/Xcode-27.0.0-Beta.5.app`，和现有的 Xcode 26.6 并存。
命令行想指定用哪个，加前缀就行（不必 `sudo xcode-select`）：

```bash
DEVELOPER_DIR=/Applications/Xcode-27.0.0-Beta.5.app/Contents/Developer xcodebuild ...
```

### ⚠️ Xcode 27 里没有 Simulator.app 了，模拟器只能无头跑（2026-08-17 记）

`/Applications/Xcode-27.0.0-Beta.5.app/Contents/Developer/Applications/` 下**没有 Simulator.app**

所以自测改成**用启动参数把界面摆到想看的状态，再截图**。参数清单在 `DemoData.swift` 的 `DevFlags`：

```bash
SIM=9AF63CDD-A064-4C4D-9038-AB631455A8B8
B=com.shize.ExpenseTracker

xcrun simctl launch $SIM $B -seedDemo -openSheet tags          # 弹出「记一笔」+ 标签选择器
xcrun simctl launch $SIM $B -seedDemo -openSheet edit          # 弹出「编辑」（只有编辑态才有「创建时间」那一行）
xcrun simctl launch $SIM $B -seedDemo -unlockPrivate            # 以「私密模式已解锁」启动（连点三下那个手势这台机器做不了）
xcrun simctl launch $SIM $B -seedDemo -openSheet export         # 弹出「导出」
xcrun simctl launch $SIM $B -seedDemo -openSheet export -dumpExport   # 顺便把 CSV / 长图渲出来落盘，供命令行核对
xcrun simctl launch $SIM $B -seedDemo -openSheet filter        # 弹出「按标签筛选」
xcrun simctl launch $SIM $B -seedDemo -filterTags 出差,可报销    # 带着标签筛选启动，核对去重口径
```

要往**落盘的**库里塞测试数据（比如复现升级迁移），可以直接改 SQLite：
容器路径用 `xcrun simctl get_app_container $SIM $B data` 拿，库在 `Library/Application Support/default.store`。
注意 Core Data 的时间戳基准是 2001-01-01 UTC（Unix 时间戳要减 978307200），插完记得
`update Z_PRIMARYKEY set Z_MAX=<最大主键> where Z_ENT=<实体号>`。
另外 `xcrun simctl install` 会**换掉整个数据容器**（数据没了），所以要先装 app、再塞数据。

### 关于无线安装（2026-08-17 更新：真因不是 Xcode，是公司 Wi-Fi 拦发现流量）

先纠正 08-13 那版结论。当时以为「Xcode 砍掉了无线安装」，方向是错的：

- **配对关系一直还在**，不需要为了配对再插线：
  `connectionProperties` 里 `pairingState: paired`、`authenticationType: manualPairing`，
  手机的开发者模式也还是 `enabled`。缺的只是**网络通道**（`tunnelState: unavailable`）。
- **命令行明确支持按网络主机名配对**：`xcrun devicectl manage pair --device <dns_name>`
  （`devicectl manage` 下面还有 `unpair`）。所以不存在「功能被删掉」这件事。
  ⚠️ Xcode 27 里连 Simulator.app 都没有了，`Window → Devices and Simulators` 那类老教程一律别信。

真正的拦路虎是**公司 Wi-Fi 把 Bonjour（设备互相发现用的那套广播）过滤掉了**。取证：

- 用 `dns-sd -B _companion-link._tcp local` / `_airplay._tcp` / `_remoted._tcp` 各盯一分钟，
  **只看得见本机自己**。办公室 ARP 表里有 138 个邻居，不可能一台苹果设备都没有。
- 排掉「是自己拦自己」：`socketfilterfw` 显示本机防火墙是关的。
- 排掉「网络压根不通」：`ping 224.0.0.1` 有几十台机器回，`ping 224.0.0.251`（mDNS 那个多播组）
  也有十几台回 —— 说明多播能跨这个 AP，那些机器的 Bonjour 也在正常跑。

**结论：普通流量互通，偏偏 mDNS 这一类被单独掐掉了**（企业 AP 常见配置）。手机就算挂在同一个
Wi-Fi 上，Mac 也发现不了它，所以在公司网络下无线安装走不通，只能插线。

⚠️ **下面这条还没实测**：换成不过滤 Bonjour 的网络（**手机自己的个人热点**，或家里的 Wi-Fi）
大概率就能无线装 —— 手机当 AP 时中间没有公司 AP，发现流量自然通。查到的东西里没有任何一条
会阻止这条路，但没验过就不能当结论。要验的话：手机开热点 → Mac 连上去 → `xcrun devicectl list devices`
看设备是不是变成可用、`tunnelState` 有没有起来 → 然后照常跑 `tools/install-to-iphone.sh`（脚本不用改，
它只按 UDID 找设备，不关心是线还是网络）。

目前的做法：**续期时插一次线**，跑一遍 `tools/install-to-iphone.sh`，全程约 1 分钟。

### ⚠️ 光跑脚本**不一定**能续上签名（2026-08-17 实测踩到）

当天签名还剩不到 3 天，跑完整个脚本、app 也装上了，但**到期时间一动没动**——
描述文件还是 4 天前那一份（UUID 都没变）。原因：苹果那边看本地这份**还没过期**，就直接复用，
不给发新的。要是没核对，两天后照样打不开，而且会误以为「我明明续过了」。

**破法**：把本地那份描述文件删掉，逼 `xcodebuild -allowProvisioningUpdates` 重新申请。
删掉后拿到的是崭新的 7 天（当天实测：新 UUID、有效期整 7 天）。

脚本现在**自动做这件事**（第 3 步）：剩余不足 5 天就先备份旧文件、删掉、再重新申请；
留 2 天余量是因为续期必须插线，不想「刚跑完隔天出门就打不开」。申请失败会把旧文件还原回去。
跑完最后一行会打印**北京时间**的到期时间和剩余天数，不到 5 天会明确报警。

手工检查现在的签名还剩多久：

```bash
security cms -D -i ~/Library/Developer/Xcode/UserData/Provisioning\ Profiles/*.mobileprovision \
  | python3 -c "
import sys,plistlib,datetime
d=plistlib.loads(sys.stdin.buffer.read()); e=d['ExpirationDate']
print('北京时间到期：', e+datetime.timedelta(hours=8), ' 还剩', e-datetime.datetime.utcnow())"
```

### 重装不会丢账目（2026-08-17 起是实测，不再是推测）

原先 README 写「重装不清数据」是**推测**，从没经历过一次真实续期重装。08-17 那次补上了实测：
装之前把手机上的库拉下来（2 笔 / ¥51），装完再拉一次对比 —— **一模一样**。
所以这条现在可以放心。

不过还是保留了兜底：`tools/install-to-iphone.sh` 会**在装之前自动把手机上的数据拷到
`backups/<时间戳>/`**。手工备份：

```bash
xcrun devicectl device copy from --device $UDID \
  --domain-type appDataContainer --domain-identifier com.shize.ExpenseTracker \
  --source "Library/Application Support" --destination ./backups/手动备份
```

⚠️ 顺带一个坑：**模拟器上的 `xcrun simctl install` 会把整个数据容器换掉**（数据没了），
真机的 `devicectl device install app` 不会。两者行为不同，别拿一个推论另一个。

### 数据库升级发生在「首次启动」，不是「安装完」

08-17 实测：装完新版本、还没打开 app 时，手机上的库里**还没有** `ZTAG` 表；
点开 app 之后才出现（记录完好）。所以装完要真启动一次才算升级完成。

手机锁屏时 `devicectl ... process launch` 会被系统拒（报 `Locked`），脚本会重试几次并提示解锁；
实在没启动成功也没关系，手机桌面上点一下图标效果一样。
